# Публичное демо на Render Free

Публичный режим включается только `CGM_PUBLIC_DEMO=1`. Dockerfile включает его
по умолчанию. Локальный запуск без этой переменной сохраняет исторический
симулятор, исходные API и выбор SQLite через `CGM_DATABASE_URL`.

## Поведение и ограничения

- Один FastAPI раздаёт React/Vite и `/api` с одного origin. Один Uvicorn worker.
- Только вымышленные данные из `demo/synthetic.csv`: 40 точек, интервалы
  4 минуты, фиксированный UTC. Исторические данные не используются.
- На скорости ×60 весь сценарий занимает 156 секунд: нормальные значения,
  верхний диапазон, новое ухудшение, постепенное восстановление, нижний
  диапазон и отдельное низкое событие. Пороги анализатора не менялись.
- Первое уведомление появляется примерно через 24 секунды. Нажмите «Я увидел»
  до нового роста примерно на 48-й секунде. Для неспешного показа можно
  поставить паузу, подтвердить и продолжить. Повторное ухудшение оценивается
  существующей серверной политикой. Восстановление не порождает лишних повторов.
- Анонимный секрет — 32 случайных байта в `__Host-cgm_demo`: HttpOnly, Secure,
  SameSite=Strict, Path=/, без Domain. В SQLite хранится только производный
  идентификатор пользователя. Секрет нельзя передавать другим посетителям.
- История, измерения, события и уведомления ограничены владельцем. Подмена
  `run_id` возвращает пустой список; чужой notification ID — 404.
- У посетителя один контроллер и максимум одна активная симуляция. До 8
  симуляций одновременно, включая паузы; до 64 сеансов; последние 5 запусков
  на посетителя; не чаще одного нового запуска за 5 секунд.
- Сеанс живёт не более часа, удаляется после 15 минут без API-запросов.
  Очистка выполняется при следующих обращениях. Сеанс и его история удаляются
  каскадно. После перезапуска процесса старые пользователи без контроллера
  очищаются при создании новых сеансов по сроку в один час.
- Изменяющие запросы и bootstrap требуют `X-CGM-Demo: 1`; чужой Origin,
  `Origin: null` и Sec-Fetch-Site=cross-site запрещены. CORS не включён.
  Прямой POST измерений в публичном режиме запрещён.
- Новую БД приложение создаёт автоматически по фиксированному пути
  `/tmp/cgm-public-demo.sqlite3`. `CGM_DATABASE_URL` в публичном режиме
  намеренно не выбирает рабочую БД. Миграции схемы для сеансов не нужны.
- Если файл сохранился при обычном перезапуске процесса, cookie и история
  восстанавливаются, незавершённый запуск становится stopped до явного resume.
  Если файл исчез, старый cookie получает 401, frontend повторяет bootstrap,
  получает новый сеанс и сбрасывает старый выбор запуска.
- Лимиты приложения ограничивают случайную нагрузку и расход памяти. Это
  прототип для нескольких посетителей, без защиты от распределённого DoS.

Render Free засыпает после 15 минут без входящего трафика. Следующий запрос
пробуждает сервис примерно за минуту. Локальные файлы, включая SQLite,
теряются при перезапуске, новом развёртывании и засыпании. Доступны 750
бесплатных часов на workspace в месяц; есть отдельные квоты сборок и трафика.
Память Free ограничена 512 МБ, CPU мал; не повышайте число workers или лимиты
сеансов без нагрузочной проверки. Persistent disk и платная БД не нужны.

Источники: [Render Free](https://render.com/docs/free),
[описание ресурсов Free](https://render.com/articles/from-side-project-to-production-scaling-your-first-app),
[Docker on Render](https://render.com/docs/docker).

## Локальная проверка Docker

Из корня репозитория:

```bash
docker build -t cgm-public-demo:local .
docker run --rm --name cgm-public-demo -p 127.0.0.1:10000:10000 \
  --memory=512m --cpus=0.1 cgm-public-demo:local
```

Открыть `http://localhost:10000/`; health — `http://localhost:10000/health`.
Secure cookie предназначен для HTTPS. Для полной проверки cookie используйте
HTTPS reverse proxy; поддержка Secure cookie на HTTP localhost зависит от
браузера. Не отключайте Secure для публичного размещения. Через HTTP по
обычному IP эта cookie работать не должна.

Dockerfile собирает frontend на Node 22, затем копирует в Python runtime
только backend, необходимые внешние модули, симулятор, синтетический CSV и
собранный frontend. Процесс работает не от root. `.dockerignore` допускает
явный список исходных файлов и исключает `data/`, SQLite, `.env`, ключи,
виртуальные окружения, Git и локальный node_modules. Не добавляйте COPY . .
и не монтируйте локальный `data/` в публичный контейнер.

Для тестов устанавливается также httpx из requirements-dev.txt:

```bash
python -m pip install -r requirements-dev.txt
env -u CGM_DATABASE_URL -u CGM_PUBLIC_DEMO CGM_TESTING=1 \
  PYTHONPATH=backend python -m unittest discover -s tests -v
```

Набор public_demo использует собственные временные SQLite и HTTPS TestClient.
Существующие HTTP-тесты открывают localhost-порты и тоже используют отдельные
временные базы. Модели БД и оригинальный анализатор проверяются командами из README.

## Размещение на Render Free вручную

Публикация разрешена владельцем проекта после финальных проверок. Render
получает код из ветки `feature/public-demo`; объединение с main не требуется.
Авторизуйтесь самостоятельно через официальный `render login`: токен хранится
в стандартной локальной конфигурации CLI, вне проекта. Не передавайте токены
в чат, исходники или документацию.

1. Проверить diff ветки `feature/public-demo`, результаты тестов и отсутствие
   чувствительных файлов. После отдельного согласования сохранить и отправить
   эту ветку в GitHub. Merge в main для демо не требуется.
2. В Render Dashboard выбрать **New → Web Service** и подключить репозиторий.
3. Выбрать **Branch: feature/public-demo**, **Language: Docker**.
   Root Directory оставить пустым: build context — корень репозитория.
   Dockerfile Path — `./Dockerfile`.
4. Instance Type — **Free**. Оставить один экземпляр. Не создавать disk,
   Postgres, Redis или отдельный Static Site.
5. Docker Command оставить пустым: используется CMD образа. Он слушает
   `0.0.0.0:${PORT:-10000}`, явно задаёт `--workers 1` и принимает proxy headers
   от платформы. Build/Start Command для native Python не нужны.
6. Установить environment `CGM_PUBLIC_DEMO=1` (также уже задано в образе).
   Не добавлять исторический CSV, CGM_SIMULATOR_CSV, CGM_SIMULATOR_TIMEZONE,
   CGM_DATABASE_URL или секреты локального проекта.
7. Health Check Path — **/health**. **Auto-Deploy — Off**: обновлять демо
   вручную, чтобы случайный push не прерывал показ.
8. После того как Render назначит URL, можно дополнительно задать
   `CGM_PUBLIC_ORIGIN=https://ИМЯ-СЕРВИСА.onrender.com` без пути и завершающего
   slash. Это точная проверка Origin; она необязательна при штатных proxy
   headers Render. При смене домена обновить значение. Если переменная не
   задана, origin сверяется с адресом текущего запроса.
9. Запустить создание/развёртывание сервиса. Дождаться успешной сборки и health
   check. Открыть HTTPS URL, затем проверить вторым браузером или приватным
   окном: два запуска, независимая пауза, уведомления, «Я увидел», refresh.
10. Проверить ручной restart/redeploy: допустимо получить новый пустой сеанс.
    На холодном старте дождаться пробуждения и при необходимости нажать
    «Повторить подключение». Только после этого сформировать QR-код на корневой
    HTTPS URL. Перед показом открыть сайт заранее, учитывая холодный старт.

Результаты первоначальной локальной проверки — в PUBLIC_DEMO_QA.md.

## Публикация через официальный Render CLI

После `render login` и выбора своего workspace команда явно создаёт только
бесплатный Docker Web Service, без диска и дополнительных сервисов:

```bash
render services create --name cgm-assistant-demo --type web_service \
  --repo https://github.com/Arhip8/cgm-assistant \
  --branch feature/public-demo --runtime docker --plan free \
  --region frankfurt --num-instances 1 --auto-deploy=false \
  --health-check-path /health --env-var CGM_PUBLIC_DEMO=1 \
  --output json --confirm
```

Перед повторным запуском команды проверьте `render services`: если сервис уже
создан, используйте его, чтобы не создавать дубликаты. Сохраните настоящий URL
из ответа Render и проверяйте его после завершения deploy. Наличие ветки в
GitHub или успешная локальная сборка не означают, что публичная версия работает.
