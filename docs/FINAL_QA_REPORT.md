## Проверенные браузерные сценарии

1. На новой SQLite Dashboard показал доступность API, пустой график, пустые
   события и уведомления, состояние симуляции `Ожидает запуска`.
2. Выбор скорости ×3600 отображался как выбранный; API получил выбранную
   скорость при старте.
3. Кнопка запуска создала реальный серверный запуск. Dashboard синхронизировал
   `run_id`; прогресс и график начали обновляться. Журнал событий и
   информационные уведомления появились на данных CSV.
4. Кнопка «Я увидел» изменила статус уведомления; после рестарта backend
   подтверждение осталось сохранённым.
5. Пауза остановила рост сохранённого прогресса после текущей обработки:
   два последовательных чтения status показали одинаковую позицию, а число
   записей в readings совпало с ней.
6. Продолжение сохранило `run_id`, увеличило `source_index`; после остановки
   показания остались доступны через API.
7. Повторный запуск во время активности вернул HTTP 409. Два быстрых нажатия
   «Пауза» создали ровно один HTTP POST.
8. Обновление страницы во время `running` восстановило тот же `run_id` и
   активный статус; симуляция не запускалась повторно. После рестарта FastAPI
   UI восстановил состояние `stopped`, данные графика, события и уведомления;
   следующий запуск происходил только после явного нажатия «Продолжить».
9. После остановки прогресс оставался неизменным, сохранённый индекс и набор
   измерений совпадали.
10. В отдельном трёхстрочном синтетическом CSV воспроизведение дошло до конца:
    `completed`, 3 из 3; остановка завершённого запуска вернула HTTP 409.
11. Изоляция `run_id` подтверждена запросом неизвестного сеанса: получен пустой
    список.
12. На ширинах 1440, 768 и 390 px горизонтального переполнения не обнаружено.
    На мобильном экране панели расположены вертикально, кнопки управления
    занимают две колонки; график и панели событий/уведомлений остаются
    доступными.
13. Во время намеренной остановки backend Vite proxy вернул HTTP 500; после
    перезапуска API Dashboard автоматически восстановил соединение и
    отобразил сохранённый статус и данные.

На остановленном прогоне настоящего CSV сохранено 477 измерений с
непрерывными индексами `0..476`, 12 записей событий и 6 уведомлений.
Уведомления относятся к разным событиям; дубликатов `event_id` у уведомлений
нет. Один просмотренный пользователем статус уведомления пережил перезапуск.
Проверки SQLite: `PRAGMA integrity_check` — `ok`, `PRAGMA foreign_key_check` —
0 нарушений.

## Надёжность и ошибки

- Пропусков `source_index` в сохранённых измерениях не обнаружено.
- Повторная обработка / несколько быстрых UI-нажатий не создали второй запрос
  pause. Уникальность уведомлений по событию проверена по API и SQLite.
- Признаков продолжающегося воспроизведения после `stop` или shutdown не
  обнаружено: прогресс остановился; после рестарта автозапуска не было.
- При отключённом FastAPI proxy возвращает специальный HTTP 503; Dashboard
  показывает «Нет соединения с сервером. Проверьте, запущен ли FastAPI».
  После повторного запуска FastAPI с той же тестовой SQLite соединение,
  прогресс, `run_id`, измерения, события и уведомления восстановились.
- Настоящий HTTP 500 от временного upstream был пропущен через Vite без
  изменения статуса; Dashboard показал «Ошибка API 500» и описание ошибки,
  а не сообщение о потере соединения.
- Во время нормальной работы необработанных JavaScript-исключений не
  зафиксировано. В browser log есть ожидаемые неуспешные/отменённые запросы
  при ручном выключении API и перезагрузке страницы.

## Непроверенные области и оценка готовности

- Не воспроизводился весь датасет из 10 881 измерения: live-проверку реального
  CSV остановили на 477 измерениях, чтобы ограничить длительность прогона.
  Завершение на EOF проверено отдельно на коротком синтетическом CSV.
- Визуально проверена работа на указанных ширинах, но не выполнялась
  кроссбраузерная проверка в нескольких браузерах и операционных системах.
- Реальный часовой пояс CSV остаётся неизвестным. Для демонстрации необходимо
  подтвердить и задать его оператором; `UTC` в этой проверке не является
  утверждением об исходном часовом поясе.
- Не проверялись нагрузка нескольких одновременных браузерных клиентов и
  принудительное завершение процесса без штатного lifespan shutdown.

**Оценка:** основные пользовательские сценарии Dashboard и серверного
Simulation Control API готовы к демонстрации на ограниченном прогоне. Перед
публичным показом следует задать подтверждённый пояс источника. Медицинское
назначение и реальные клинические выводы не тестировались.
